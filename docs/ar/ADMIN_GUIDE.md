# دليل الإدارة

تشغيل استوديو الإدارة: الأدوار، وأول مسؤول، وتحرير المحتوى، وسير العمل التحريري، والشهادات، ومقاطع الفيديو، وسجلّ التدقيق. [English version](../ADMIN_GUIDE.md)

آخر مراجعة: 13 أكتوبر 2026. انظر أيضًا [الأمان والصلاحيات](../SECURITY_AND_PERMISSIONS.md)، والمخططات [4](../diagrams/04-roles-and-permissions.md) و[9](../diagrams/09-admin-content-workflow.md) و[10](../diagrams/10-youtube-video-curation.md).

## 1. الأدوار

| الدور | من يحصل عليه | ماذا يستطيع |
| --- | --- | --- |
| **متعلّم** | كل حساب تلقائيًا، ولا يمكن سحبه | التعلّم: التقدّم، والدروس المحفوظة، واختبارات الفهم، و«لوحتي»، وإعدادات الحساب |
| **مدرّب** | يمنحه مسؤول | دخول استوديو الإدارة. إنشاء مسودات الدروس وتعديلها. تعديل المسارات التي في حالة مسودة أو مخطَّط، وإضافة وحدات إليها. إرسال الدروس للمراجعة. إضافة مقاطع فيديو كمسودات. تعديل سجلات الشهادات غير الموثّقة. قراءة سجلّ التدقيق |
| **مسؤول** | يُنشأ عند الإعداد، أو يمنحه مسؤول آخر | كل ما يستطيعه المدرّب، وأيضًا: النشر وإلغاء النشر والأرشفة؛ تعديل المحتوى المنشور؛ توثيق معلومات الشهادات؛ نشر مقاطع الفيديو؛ منح الأدوار وسحبها |
| مساهم، مشرف محتوى | موجودان في نموذج البيانات | لا شيء بعد. ميزاتهما (المساهمات والإشراف) مخطط لها |

هذه القواعد تُطبَّق على الخادم في كل صفحة وكل إجراء إداري، وليس بإخفاء الأزرار فقط.

## 2. أول مسؤول

كل تسجيل جديد يحصل على دور متعلّم فقط، لذلك يُنشأ أول مسؤول من خارج الموقع، على يد شخص لديه صلاحية الوصول إلى الخادم. اختر إحدى الطرق التالية.

**أ. متغيرات البيئة (الأنسب للاستضافة مثل Render).** اضبط على الخادم:

<div dir="ltr">

```
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD=a-strong-password-2026   # 10+ characters, at least one letter and one number
ADMIN_NAME=Your Name                    # optional
```

</div>

عند التشغيل التالي، إذا لم يكن في قاعدة البيانات أي مسؤول:

- يُنشأ الحساب بدوري متعلّم ومسؤول، ويظهر في سجلّ الخادم `administrator created: you@example.com`.
- إذا كان هناك حساب بالبريد نفسه، يُرقّى إلى مسؤول ولا تتغير كلمة مروره.
- بعد وجود أي مسؤول تُتجاهل هذه المتغيرات.
- القيم تبقى على الخادم ولا تُرسل إلى المتصفح أبدًا.

على الخطة المجانية في Render أبقِ `ADMIN_PASSWORD` مضبوطًا، لأن قاعدة البيانات تبدأ من جديد عند كل إعادة تشغيل، فيُعاد إنشاء المسؤول منه.

**ب. سطر الأوامر (محليًا، أو من Shell في Render، أو داخل حاوية):**

<div dir="ltr">

```bash
npm run admin:create -- --email you@example.com --name "Your Name"
# asks for the password with hidden input, or reads ADMIN_PASSWORD if set
```

</div>

يرفض الأمر إذا كان هناك مسؤول مسبقًا. لإنشاء مسؤول إضافي عن قصد أضف `--additional`.

**ج. في التطوير فقط:** الأمر `npm run dev` ينشئ المسؤول التجريبي `admin@demo.qa-academy.test` بكلمة المرور `Demo-Password-2026`. الحسابات التجريبية لا تُنشأ أبدًا عندما يكون `NODE_ENV=production`.

## 3. منح الأدوار وسحبها

من الموقع (للمسؤولين): **الإدارة ← المستخدمون والأدوار**.

1. ابحث بالاسم أو البريد الإلكتروني.
2. علِّم الأدوار المطلوبة أو أزل علامتها في بطاقة المستخدم.
3. اضغط **حدّث الأدوار**.

من سطر الأوامر:

<div dir="ltr">

```bash
npm run user:role -- grant  someone@example.com instructor
npm run user:role -- revoke someone@example.com instructor
npm run user:role -- list   someone@example.com
```

</div>

قواعد الحماية (في الموقع وسطر الأوامر):

- كل حساب يحتفظ بدور متعلّم.
- لا يستطيع المسؤول سحب دور المسؤول من نفسه.
- لا يمكن سحب دور آخر مسؤول، ولا يستطيع آخر مسؤول حذف حسابه.
- كل تغيير يُكتب في سجلّ التدقيق (مثل `role.update +instructor`).

## 4. فتح الاستوديو

1. سجّل الدخول بحساب مدرّب أو مسؤول.
2. افتح القائمة التي تحمل اسمك الأول في أعلى الصفحة واختر **الإدارة**.

صفحة **نظرة عامة** تعرض:

- الأعداد: المسارات، والدروس، والدروس المنشورة، وما ينتظر المراجعة، والمستخدمين، والمقاطع؛
- الدروس التي **بانتظار المراجعة**؛
- **أحدث التغييرات**.

الاستوديو يعمل باللغتين بالميزات نفسها: `/ar/admin` بالعربية و`/admin` بالإنجليزية.

## 5. تحرير الدروس

**الإدارة ← المسارات والدروس** تعرض كل مسار ووحدة ودرس، مع الحالة واللغات المتوفرة.

**إنشاء درس:** اختر **درس جديد**، ثم:

1. اختر الوحدة.
2. أدخل المعرّف في الرابط (أحرف إنجليزية صغيرة وأرقام وشرطات) والعنوان والملخّص.

يُنشأ الدرس كـ **مسودة**.

**تعديل درس:** اختر **تعديل الدرس**. في المحرّر:

- حقول مشتركة: وقت القراءة، والمستوى، والمهارات، والترتيب، وتاريخ المراجعة؛
- قسم لكل لغة.

| الحقل | الصيغة |
| --- | --- |
| نص الدرس | Markdown. استخدم عناوين `##` و`###` (تصبح روابط «في هذه الصفحة»)، وكتل الشيفرة مع اسم اللغة (` ```ts `) |
| الأهداف، المتطلبات السابقة | عنصر في كل سطر |
| المصطلحات الأساسية | سطر لكل مصطلح: `المصطلح :: التعريف` |
| الأخطاء الشائعة | سطر لكل خطأ: `الخطأ :: التصحيح` |
| التمرين | العنوان، والوصف (Markdown)، والإجابة النموذجية (Markdown) |
| اختبار الفهم | JSON (انظر أدناه) |
| المراجع | سطر لكل مرجع: `العنوان \| https://الرابط \| الناشر` (روابط https فقط) |

صيغة اختبار الفهم (JSON):

<div dir="ltr">

```json
[
  {
    "id": "q1",
    "prompt": "يقبل الحقل الأعمار من 18 إلى 65. أي مجموعة تغطي الحدّين؟",
    "options": [
      { "id": "a", "text": "17، 18، 65، 66" },
      { "id": "b", "text": "18، 40، 65" },
      { "id": "c", "text": "0، 100" }
    ],
    "answer": "a",
    "explanation": "تحليل القيم الحدّية بقيمتين يختبر كل حدّ وأقرب قيمة غير صالحة بجانبه."
  }
]
```

</div>

يجب أن يستخدم اختبار الفهم العربي **معرّفات الأسئلة والخيارات والإجابات نفسها** التي في الإنجليزي، ويُترجم النص فقط. هكذا يبقى التصحيح والمحاولات المحفوظة متطابقة في اللغتين.

إذا كان هناك خطأ (JSON غير صالح، أو سطر بصيغة خاطئة، أو معرّف مستخدم في المسار نفسه)، يسمّي المحرّر المشكلة ويُبقي كل ما كتبته.

**المعرّف في الرابط** يمكن تغييره حتى أول نشر للدرس. بعد ذلك يُقفل، لأن تقدّم المتعلّمين ودروسهم المحفوظة مرتبطة بـ `path/lesson`.

## 6. سير العمل التحريري

<div dir="ltr">

```
planned ──► draft ──► in review ──► published ──► archived
              ▲  ◄──────┘  ◄─────────────┘            │
              └──────────── restore as draft ◄────────┘
```

</div>

| الإجراء | من حالة | إلى حالة | من يستطيع |
| --- | --- | --- | --- |
| أرسل للمراجعة | مسودة | قيد المراجعة | مدرّب، مسؤول |
| انشر | مسودة، قيد المراجعة | منشور | مسؤول |
| أعِد إلى المسودات | قيد المراجعة، منشور | مسودة | مسؤول |
| أرشِف | مخطَّط، مسودة، قيد المراجعة، منشور | مؤرشف | مسؤول |
| استعِد كمسودة | مؤرشف، مخطَّط | مسودة | مدرّب، مسؤول |
| علِّم كمخطط فقط | مسودة | مخطَّط | مدرّب، مسؤول |

لوحة **سير العمل** في صفحة التعديل تعرض فقط الإجراءات المسموحة لك من الحالة الحالية.

**قائمة التحقق قبل النشر.** يُرفض النشر، مع ذكر الأسباب، ما لم يكن في الدرس:

- محتوى إنجليزي **وعربي**؛
- نص درس لا يقل عن 300 كلمة في كل لغة؛
- هدفان على الأقل وخطآن شائعان على الأقل؛
- تمرين مكتمل؛
- ثلاثة أسئلة فهم على الأقل، بمفاتيح إجابات متطابقة في اللغتين؛
- مرجع واحد على الأقل؛
- مهارة واحدة على الأقل؛
- تاريخ مراجعة.

تغييرات المحتوى المنشور تظهر على الموقع فورًا. الدروس المخطَّطة تظهر في صفحة المسار كمخططات أولية؛ أما المسودة وقيد المراجعة والمؤرشف فمخفية عن الجمهور.

## 7. المسارات والوحدات

في **تعديل المسار** تستطيع تغيير:

- المعرّف في الرابط (يُقفل بعد وجود دروس منشورة في المسار)؛
- نطاق المستوى، والمهارات، والحالة، والترتيب؛
- الترجمتين: العنوان، والملخّص، والهدف، والمتطلبات السابقة، والنواتج، والمحطّات.

وتستطيع إضافة وحدات (معرّف، وعنوان وملخّص بالعربية والإنجليزية).

- المدرّب يعدّل المسارات التي في حالة مسودة أو مخطَّط. المسؤول وحده يعدّل مسارًا منشورًا، أو ينقل مسارًا إلى حالة النشر أو الأرشفة أو منها.
- المسار المنشور الذي فيه دروس منشورة يظهر في قائمة المسارات. المسار المخطَّط يظهر بعبارة «قيد الإعداد».
- المسارات الجديدة والنماذج والمشاريع التدريبية تُضاف حاليًا عبر ملفات البيانات (`seed/content/`) ثم نشر جديد. الاستوديو لا ينشئها بعد ([القيود المعروفة](../KNOWN_LIMITATIONS.md)).

## 8. الشهادات

**الإدارة ← الشهادات** تعرض كل السجلات مع حالة التوثيق.

- أي شخص لديه صلاحية الاستوديو يستطيع تعديل ملخّص السجل **غير الموثّق** والجمهور المستهدف والمتطلبات وخطة الدراسة وأسئلة التدريب.
- المسؤول وحده يستطيع توثيق سجل، أو تعديل سجل موثّق.
- التوثيق يتطلب:
  - معلومات الامتحان: عدد الأسئلة، ومجموع النقاط، ودرجة النجاح، والمدة، والوقت الإضافي لغير الناطقين بلغة الامتحان إن وُجد؛
  - رابط المصدر الرسمي؛
  - تاريخ المراجعة؛
  - علامة على «تحققت من هذه المعلومات على الصفحة الرسمية في تاريخ المراجعة أعلاه».
- السجلات غير الموثّقة لا تعرض معلومات الامتحان على الموقع أبدًا، بل ترسل الزائر إلى الصفحة الرسمية.

السياسة التحريرية:

- تحقّق من كل معلومة على صفحة ISTQB® نفسها.
- لا تعرض الرسوم أبدًا، لأنها تختلف حسب جهة الامتحان والبلد.
- لا تنسخ أسئلة الامتحانات النموذجية الرسمية: اكتب أسئلة تدريب أصلية وضع رابطًا للنماذج الرسمية.

## 9. مقاطع الفيديو

**الإدارة ← المقاطع ← أضف فيديو.**

1. الصق رابط يوتيوب (`youtube.com/watch?v=…` أو `youtu.be/…`) أو معرّف الفيديو المكوّن من 11 حرفًا. روابط المواقع الأخرى مرفوضة، ولا يوجد رفع ملفات.
2. أدخل العنوان كما نُشر على يوتيوب حرفيًا، واسم صاحب القناة، ورابط القناة.
3. اكتب ملاحظة قصيرة بالعربية والإنجليزية عن سبب فائدة المقطع.
4. أضف الدروس المرتبطة، معرّف درس في كل سطر (مثل `qa-foundations/decision-tables`)، فيظهر المقطع في تلك الدروس.
5. يُحفظ المقطع كـ **مسودة**. ينشره المسؤول بعد أن:
   - يتحقق من الرابط والعنوان وصاحب القناة على يوتيوب؛
   - يعلّم «تحققت اليوم من الرابط والعنوان وصاحب القناة على يوتيوب»، فيُسجَّل تاريخ التحقق.

المقاطع تُعرض بالرابط والتضمين فقط، بوضع الخصوصية المحسّن، وتُحمَّل عندما يضغط المتعلّم تشغيل. لا تُنزَّل ولا يُعاد رفعها أبدًا.

**المحتوى المرفوع:** لا يوجد رفع ملفات في المنصة. الوسائط تقتصر على روابط يوتيوب والنماذج المضمّنة في `public/templates/`. رفع المستخدمين مع الإشراف مخطط له ([المخطط 11](../diagrams/11-user-video-uploads.md)).

## 10. سجلّ التدقيق

**الإدارة ← سجلّ التدقيق** يعرض كل تغيير:

- متى، ومن؛
- الإجراء: `lesson.create`، `lesson.update`، `lesson.status`، `path.update`، `module.create`، `certification.update`، `video.create`، `video.update`، `role.update`، `admin.bootstrap`، `account.delete`؛
- العنصر، مع تفاصيل مثل `in_review → published`.

تبقى السجلات حتى لو حُذف المستخدم لاحقًا، وعندها يظهر في عمود «من» اسم «النظام».

## 11. بيانات البداية وتعديلات الاستوديو

عند تشغيل الخادم تُضاف بيانات البداية الناقصة فقط، و**لا يُستبدل أبدًا** ما عدّلته في الاستوديو.

الطريقة الوحيدة لاستبدال المحتوى من ملفات البيانات هي الأمر الصريح `npm run db:seed -- --force-content`، وهو يلغي تعديلات الاستوديو. استخدمه على نسخة تجريبية فقط، أو عندما تقصد ذلك فعلًا. انظر [DATABASE.md](../DATABASE.md#5-seeding-rules).

## 12. إعادة تعيين كلمة المرور للمتعلّمين

الموقع لا يرسل بريدًا إلكترونيًا بعد. عندما يطلب متعلّم إعادة تعيين كلمة المرور:

- يُكتب الرابط في سجلّ الخادم (`[mail:outbox] to=…`) ويبقى صالحًا 30 دقيقة.
- على Render: افتح تبويب **Logs** في الخدمة، وابحث عن السطر الخاص ببريد المتعلّم، وأرسل له الرابط عبر قناة موثوقة.
- محليًا: افتح `/dev/outbox`.
